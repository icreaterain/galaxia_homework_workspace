# GraphQL Schema Sync

Keeps the GraphQL schema contract in sync between the backend (schema owner) and the frontend (codegen consumer). Use whenever a GraphQL resolver, model, or field changes in `cloudtalk_homework_be`, or when `src/generated/graphql.ts` in `cloudtalk_homework_fe` appears stale.

## Schema Ownership

`schema.graphql` lives in the **`cloudtalk_homework_be` repo** and is committed there. It is the single source of truth for the GraphQL API contract.

```
cloudtalk_homework_be/
  schema.graphql          ← committed artefact, source of truth
  (generated by `pnpm run schema:export` from NestJS code-first decorators)

cloudtalk_homework_fe/
  src/generated/graphql.ts  ← gitignored, regenerated from schema.graphql
  (generated by `pnpm run codegen`, which reads schema.graphql from BE repo)
```

**The FE never has its own copy of `schema.graphql`.** It always reads from the BE repo:

| Context | How FE gets `schema.graphql` |
|---------|------------------------------|
| Local dev | sibling directory `../cloudtalk_homework_be/schema.graphql` |
| CI (quality + deploy) | `git clone --depth=1 <BE repo>` into `../cloudtalk_homework_be/` |

## When to Use

- Added or modified a `@ObjectType`, `@Field`, `@InputType`, `@Resolver`, or `@Query` in the BE
- Added a new query document (`.queries.ts`) in the FE
- Getting type errors in the FE that reference `src/generated/graphql.ts`
- CI fails on "schema freshness check" (`git diff --exit-code schema.graphql`)
- Codegen output is missing a type or field

## Process

### Step 1 — Export the schema (in `cloudtalk_homework_be`)

After changing any NestJS decorator that affects the schema:

```bash
cd cloudtalk_homework_be
pnpm run schema:export
git diff schema.graphql     # review what changed
git add schema.graphql
# include in the same commit as the resolver/model change, or as a follow-up commit
git commit -m "chore(graphql): export updated schema"
```

CI enforces this: `pnpm run schema:export && git diff --exit-code schema.graphql` fails the build if `schema.graphql` is not up to date with the decorators.

### Step 2 — Regenerate typed services (in `cloudtalk_homework_fe`)

Once the BE branch with the updated `schema.graphql` is available (merged to main or accessible as a sibling locally):

```bash
cd cloudtalk_homework_fe
pnpm run codegen            # reads ../cloudtalk_homework_be/schema.graphql
                            # writes src/generated/graphql.ts (gitignored — do not commit)
```

### Step 3 — Verify type-check passes

```bash
cd cloudtalk_homework_fe
pnpm exec tsc --noEmit -p tsconfig.app.json
```

Fix any type errors introduced by schema changes.

## Local Setup Requirement

For codegen to work locally, the BE and FE repos must be siblings on disk:

```
cloudtalk_homework/             ← workspace root (this repo)
  cloudtalk_homework_be/        ← BE submodule
  cloudtalk_homework_fe/        ← FE submodule
```

If working directly in the FE submodule directory and `../cloudtalk_homework_be/schema.graphql` doesn't exist, run from the workspace root:

```bash
git submodule update --init --recursive
```

## Breaking Change Protocol

A breaking change removes or renames a type, field, or query the FE currently uses.

1. Grep FE query documents for the removed/renamed item:
   ```bash
   rg '<old-field-or-type>' cloudtalk_homework_fe/src/app/features
   ```
2. Update the query document (`features/*/graphql/*.queries.ts`) to use the new name/structure
3. Run `pnpm run codegen` — generated types will reflect the new schema
4. Fix any component or service code that used the old type shape
5. Run the full FE quality gate before creating a PR

Never merge a FE PR that depends on a BE schema change that has not yet been merged to `main`.
