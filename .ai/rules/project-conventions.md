# Project Conventions

Always applies to: all files in both repositories.

## Commit Messages

Format: `<type>(<scope>): <subject>`

Types: `feat` `fix` `refactor` `test` `docs` `chore` `perf`

BE scopes: `auth` `reviews` `products` `db` `api` `health` `common`
FE scopes: `auth` `reviews` `products` `shared` `graphql` `fe`
Workspace scopes: `workspace` `docs` `adr`

### Subject must be entirely lower-case — no exceptions

`commitlint` enforces `subject-case: lower-case` in both repos. Every character in
the subject line must be lowercase, including acronyms and class/type names.

```
# ✅ CORRECT
feat(auth): implement jwt auth with silent refresh
fix(api): add missing cors header for graphql endpoint
refactor(reviews): extract aggregate recalc into helper
docs(adr): add adr 009 hybrid rest+graphql

# ❌ WRONG — commit will be rejected
feat(auth): implement JWT auth with silent refresh    ← "JWT" uppercase
fix(api): fix AuthService initialization             ← "AuthService" uppercase
feat(fe): add ReviewFormComponent                    ← "ReviewFormComponent" uppercase
```

When writing subjects, convert:
- Acronyms: `JWT` → `jwt`, `API` → `api`, `URL` → `url`, `REST` → `rest`, `GraphQL` → `graphql`
- Class/component names: `AuthService` → `auth service`, `ReviewForm` → `review form`

The body lines (after the blank line) are not checked — class names there are fine.

## Never Edit

- `dist/` directories in either repo
- `src/generated/` in the FE repo — gitignored; run `pnpm run codegen` locally and in CI
- `prisma/migrations/` auto-generated files — use `prisma migrate dev` to generate

## Environment Variables

- `.env.example` is committed; `.env` and `.env.local` are gitignored
- `.env.local` overrides `.env` for the same key (machine-specific values, e.g. Supabase URLs)
- Nest's `ConfigModule` loads both files; Prisma scripts use `dotenv-cli` with `-e .env -e .env.local`
- Never commit real secrets — use placeholder values in `.env.example`

## API Split — Hybrid REST + GraphQL

REST (`/api/*`) owns all **writes** (commands):
- ✅ `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`
- ✅ `POST /api/products/:id/reviews`, `PUT /api/reviews/:id`, `DELETE /api/reviews/:id`
- ❌ Never add GraphQL mutations for operations that belong in REST controllers

GraphQL (`/graphql`) owns all **reads**:
- ✅ `product(id)`, `products(filter, pagination)`, `myReviews(pagination)`
- ✅ Nested resolvers: `Product.reviews`, `Product.ratingDistribution`
- ❌ Never add REST GET endpoints for data that belongs in GraphQL queries

## GraphQL Conventions

- Schema generated **code-first** from NestJS decorators; never edit `schema.graphql` manually
- Pagination: Relay cursor connections (`first`/`after`, `edges`/`pageInfo`) — no offset pagination
- After schema changes: run `pnpm run schema:export` (BE) then `pnpm run codegen` (FE)
- `src/generated/` is **gitignored** — generated in CI (`pnpm run codegen` runs before tsc) and locally after clone

## TypeScript

- `strict: true` in both repos. No `any`. No implicit returns.
- Explicit return types on all public service and controller methods.

## Cross-Repo Changes

Backend API contract changes must be merged before frontend changes that depend on them.
See `.ai/skills/cross-repo-change/SKILL.md` for the full protocol.

## Agentic Documentation

After any significant architectural decision, add a file to `adr/` and update the index in `adr/README.md`.
Update `ARCHITECTURE.md` only when the current system state changes (stack, data model, API surface).
After any change to structure, ports, env vars, or conventions, update `WORKSPACE.md`.
