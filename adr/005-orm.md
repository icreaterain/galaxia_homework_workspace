# 005 — Prisma as the ORM

**Date:** 2026-03-31
**Status:** Decided

## Context

The project needs database access with TypeScript support, a reliable migration story,
and clean integration with NestJS.

## Decision

Use **Prisma** as the ORM and schema migration tool.

- `schema.prisma` is the single source of truth for the database schema.
- `prisma migrate dev` generates SQL migrations from schema diffs and runs seed scripts.
- The Prisma-generated client provides a fully typed query API with autocompletion.
- `PrismaService` (extends `PrismaClient`) is registered as a NestJS global module,
  injected into all feature services.

## Trade-offs

- **Vs TypeORM:** Prisma's generated client is more type-safe (no runtime decorator
  reflection errors). TypeORM's migration generation is less reliable in practice.
  TypeORM pairs naturally with NestJS decorators but couples the data layer to the
  framework; Prisma is framework-agnostic.
- **Vs Knex:** Prisma provides higher-level abstractions with stronger typing. Knex
  offers more control but requires manual type definitions.
- **Cold-start cost:** The Prisma client is large. Negligible for this project; would
  matter in a serverless environment with strict cold-start budgets.

## Alternatives considered

- **TypeORM:** Considered as the natural NestJS companion but rejected due to less
  reliable type inference and migration tooling.
- **Knex:** Rejected — query builder only; lacks the schema-migration and type-generation
  features that Prisma provides.
- **Drizzle:** Valid modern alternative; Prisma was chosen for its larger ecosystem and
  more mature migration story.
